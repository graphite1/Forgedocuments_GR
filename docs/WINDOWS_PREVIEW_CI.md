# Windows preview CI

The user approved a branch-limited GitHub Actions Windows build and prerelease publication on 2026-10-15 at 22:38:20 UTC. This adds no PAT, signing key, GRHub update or paid runner. The repository is public; GitHub's standard Windows runner is free under the published public-repository policy. The job uses `windows-2025`, a 30-minute timeout and no Actions artifact storage. See [GitHub-hosted runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners).

Only pushes changing `.github/workflows/windows-preview.yml` on `codex/cloud-successor-1.3.13` start this workflow. It does not run on main, PRs or tag creation. A concurrency group serializes executions. Before installation/build, a guard refuses existing tags/releases. No clobber, tag replacement or release deletion is implemented.

The workflow pins official checkout/setup-python actions by commit. Its source SHA is a full, audited implementation commit, checked out explicitly. The workflow-only commit is separate from the release source. The release tag points to that implementation commit. This also avoids requesting workflow-write permission from the job's built-in token when releasing a source commit that does not modify workflows. Workflow installation itself still requires an existing connection with workflow-write permission. No new credentials are provisioned.

The isolated Windows job installs the repository's pinned build dependencies with Python 3.14 x64, runs `verify_cloud.py --cid-font --headless --report <temporary path>`, and invokes `tools/build_windows.py --unsigned --prerelease-preview`. It never calls the signing-key path. The job's temporary `GITHUB_TOKEN` is supplied only to the repository guard and release steps. The workflow uses `contents: write` to create the requested release, with other permissions omitted.

`tools/preview_release.py audit` checks the exact seven ZIP members, CRC and per-file hashes, source definitions, both print fonts and all approved background/AKTIO assets inside the EXE. It rejects original PDFs, workbooks, DBs, private folders and key files. PyInstaller's base_library.zip is allowed only as a CRC-valid container of standard-library .pyc entries; arbitrary ZIPs remain rejected. It then extracts the ZIP to a fresh temporary application directory, isolates APPDATA/LOCALAPPDATA/install root, and runs the extracted EXE with `--headless-diagnostic`. Tk/Toplevel creation is prohibited. If MS Gothic/Meiryo are absent, the diagnostic explicitly uses the CID substitute and records that Windows fallback appearance remains unverified. No font is installed.

`desktop_diagnostic` dispatches AKTIO to its data-specific checks; `storage_diagnostic` uses AKTIO's controller/document contract and verifies reopening separately. Their desktop GUI portions are not executed by this CI. Headless tests cover the new dispatch and controller path using fake widgets.

Publication initially creates a draft with `prerelease=true`, `make_latest="false"` and the exact source SHA. Only the Windows ZIP, SHA256SUMS.txt and public-safe preview-validation.json are uploaded. Draft asset bytes are downloaded and compared with the local audited bytes before publication. Redirects strip authorization when the host changes. The draft is then published with the same nonlatest prerelease flags. Each public download is fetched without authorization, compared byte-for-byte and by SHA256/GitHub digest, the tag's actual commit is resolved, and ZIP/manifest content is checked again. Failure stops the job; partial drafts are left intact for review and are not silently overwritten.

Physical printing, original-PDF overlay and Windows 10/11 desktop GUI remain unverified even after a successful packaged headless diagnostic. The exact execution evidence belongs in preview-validation.json and the Actions run, not an assumed success statement.

Windows checkout uses repository attributes to retain LF bytes in hashed JSON/assets. Test reads explicitly use UTF-8, and storage path assertions resolve Windows short-name aliases before comparison. The first cloud attempt stopped before building on these portability checks; a corrected source SHA must pass fresh Windows execution before publication.
