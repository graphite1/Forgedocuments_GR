# 1.3.13 observed-font and CI source validation

The parent supplied the formally acquired TTF as compressed bytes. Local decompression yielded exactly 20,736 bytes with SHA256 `24112fd704e2ac9dfc6ca4e721c54f2086125b08be8f087a69b12b17df827836`. The actual font parser confirmed the 46 explicit printable characters, including 角文・殿・普通・配合計画書NO. Unlisted characters, NBSP aliases and cmap sentinels are not added to advertised coverage. Every existing 13-character glyph's raw glyf bytes and decoded advance were compared with the approved numeric font and were identical. The original font bytes were not modified. Source PDFs and specimen images were not rechecked in this cloud; the separately drawn check remains inferred.

`python -B verify_cloud.py --cid-font --headless --report <temporary summary>` passed: **162 tests; 126 passed, 36 skipped; 53.854 seconds**. The skips are 34 GUI-dependent checks and 2 signing/Windows-update checks. They are not successful verification. Actual Tk creation is intercepted. All test data is synthetic and isolated.

New diagnostic coverage exercises all three forms through the real headless entry point, the desktop dispatcher for AKTIO, and AKTIO's independent controller save/reopen contract using fake widgets. The release helper's tests reject extra ZIP files, altered payloads, mismatched embedded assets, original PDF inclusion, existing release/tag targets, private repositories, source/tag mismatches and altered public downloads. Redirect handling removes authorization on cross-host redirects. Public downloads are tested without authorization. These are local automated checks; they do not mean that a Windows build or GitHub release has already run.

The current implementation defaults new Tomei profiles to the observed 46 characters and migrates the earlier basic 13-character profile once, retaining settings history and input values. Explicit numeric-only/custom/standard selections stay intact. Mixed-font PDF tests validate observed Japanese and mix-plan-number output, black input/blue artwork separation, footer notices and inferred checks. Tests that previously assumed one PDF span per field now accept legitimate per-character font runs and still verify text and color.

The branch-limited workflow will be added in a separate commit after this audited implementation commit. Actual Windows build, bundled EXE execution and release download evidence must come from the Actions run and its `preview-validation.json`. Desktop GUI, physical printing, Windows 10/11 UI and original-PDF overlay remain unverified.
