## 実装

- 単票・選択・全件・設定試験のプレビューと印刷で生成ごとに固有の PDF 名を使う。表示は PDF のメモリコピーを開く。キャンセル後も次の出力を妨げない。
- Windows 配布版の重複起動は、同一インストールで共有する名前付き mutex を使う。旧 `running.lock` の読み取り・書き込みをしない。二重起動側は案内を表示して通常終了する。
- AC の安定 ID `ac_toyoake` に限定して住所初期値を追加。様式名と社名に依存しない。独自の住所・連絡先・寸法・表示設定は保持する。SQLite 側の設定を優先し、移行履歴を保存する。
- ランダム印字は初期 OFF。横・縦の最大ずれ幅を別々に0〜2mmで指定する。値の内容は変更せず、同じデータ集合なら同じ位置になる。枠端ではずれを抑え、縮小時は印字位置も一緒に縮小する。
- 全帳票共通の用紙・縦横・行列・余白・間隔・原寸／縮小。A4 の2行×2列は AC の原寸では入らないため、縮小を明示的に選ぶ。順番は左上から右、次に下。最終用紙の端数枠は空欄。
- 帳票単位の入力候補、編集可能な既定値、新規入力で編集不可の固定値。過去の記録は保持する。候補外の文字・数値も入力可能。日付・時刻・画像は固定しない。
- 一覧と一括出力を初期画面にし、CSV の正確な実績を一括取込できる。選択単票出力・単票入力も残す。集計は伝票番号、件数、単位別数量を同じ記録集合から計算する。

## 確認方法と制約

既存依存を使い、隔離した一時フォルダーで `verify_cloud.py` を実行する。クラウドには Windows 用フォントがなく、既存 Noto CJK は ReportLab で扱えない CFF 形式のため、`--cid-font` で既存の日本語 CID フォントをテスト専用に使う。既存の Xorg dummy ドライバーで Tkinter を検証する。新規ツールのインストールや本番導入はしていない。

既存 `verify_platform.py` の新しい一時署名鍵を要する2件は実行しない。代わりに公開済み1.3.0の既存署名検証と改ざん拒否、ZIP パスとハッシュの試験を行う。Windows の実際の mutex、プリンター実機、EXE の起動・更新は別途確認が必要。

## 今回の実行結果（2026-10-14）

`DISPLAY=:99 python -B verify_cloud.py --cid-font` は62件実行、60件成功、2件保留、41.894秒。保留は新しい一時署名鍵を必要とする過去の署名生成試験と署名付きEXE準備試験。公開済み署名の検証と改ざん拒否、ZIPのハッシュ・パス検証は今回の成功試験に含む。

確認環境はPython 3.12.14 / ReportLab 4.4.9 / PyMuPDF 1.26.6 / Pillow 12.3.0 / cryptography 50.0.0。requirementsのWindows指定バージョンとの一致を主張しない。

今回確認したこと：内容を変更した連続12回プレビューと以前のPDFを開いた状態、印刷・保存キャンセル後の再プレビュー、固有パスとロック時の後処理、既定住所と社名・様式名変更、矛盾する旧住所設定の保持、SQLite・既存記録保持、別帳票への漏れ防止、横縦ランダム位置と入力値保持、用紙寸法と倍率・順番・端数枠、プレビューと保存PDFの画素一致、候補・固定値・履歴保持、一括取込の原子性と単位別集計、指定色と手書き欄・画像の出力除外。Windows mutexはAPI模擬試験でありWindows実機試験ではない。

単票1ページとA4の2行×2列・5件2ページをテスト専用データで生成し、生成画像を目視確認した。原本比較ではない。Tkinterウィジェットの操作と設定スクロールを確認したが、クラウドのGUI日本語フォント表示はWindowsと比較していない。

旧設定で住所スカラーと従来固定文が矛盾する場合は、移行で勝手に解決しない。両方の設定と以前に印字されていた文字を維持し、JSONで確認できるようにする。
