# 東名太平洋生コン・納入書（計画）の背景合成候補

現在の方式は、原票から青い固定印字の実画素だけを抽出した背景画像に、利用者が入力した黒い納入予定値をmm座標で重ねるPDF合成です。社名・表題・住所・認証文字列・罫線を文字や図形で描き直す旧方式は生コン出力では使いません。欠けた字・線の補完、OCR結果やAIによる再描画も行いません。

各伝票の外枠下部に読める「納入書（計画）」を表示します。着時刻・署名2欄は入力・CSV・描画を禁止し、背景の対応する値領域も毎回白くします。固定の時分単位と署名見出しの位置はマスクから分けます。青い手書きが固定印字と同色なら色分離だけでは区別できず、実物確認済みの清掃背景が必要です。利用者のデータや実績を乱数で創作する機能はありません。

## 分離した構成

- `templates/tomei_taiheiyo.json`: 42項目の型・入力役割・空欄保護と背景状態。37項目は黒入力、発行元と原票認証文字列の2項目は参考設定、着時刻・署名3項目は入力不可。青固定2項目の設定文字列は出力を描き直す用途には使いません。
- `templates/tomei_taiheiyo.coordinates.json` / `input_coordinates.py`: mm単位の黒入力と選択記号の座標。年月日・時分を分割配置。画面用に定義を読み込むと内部座標へ変換され、保存済み設定には変換後の座標を保持します。
- `blue_background.py`: 原票画像/PDFの青画素抽出、確認した回転角の適用、外枠切り出し。元の青の色を保持し、黒・赤・灰色を除去します。回転候補の推定は提案だけで自動適用しません。
- `background_assets.py`: PNG、SHA256、実寸、確認状態、由来、処理履歴をまとめた背景設定。描画時にも青画素抽出と空欄マスクを適用します。
- `background_compositor.py` / `core.py`: 原寸の背景描画、黒文字の重ね合わせ、出力の原子的保存。背景がない・未確認・壊れている場合は古い描き直し方式へ戻らず停止します。
- `page_layout.py`: A5原寸、用紙・行列・間隔・縮小と端数枠。背景と文字を同じ倍率で変換します。
- `tomei_defaults.py`: 既存生コン設定へ背景方式の項目だけを追加。独自の値・座標・候補・固定値・入力履歴は変更しません。

## 現在の資料と不足

直接添付された固定レイアウト説明図は会話内で視認済みです。社名は右側の大きく太いゴシック風、住所はその下の一行、TELは中央、表題は明朝風、青は水色寄り青緑、納入場所の行に左の縦区切りがないこと、年月日・時分・台目、縦の備考、配合種別の見出しと配置を確認しました。

この図は原票ではなく、黒字の納入値・署名・着時刻を取り除いた比較説明資料です。消去周辺に青印字の欠けがあり、配合表の小字・細い罫線や内部結合セル境界もかすれています。JIS画像は位置を示す枠だけです。これらを完全な背景へ自動復元できる資料とはしていません。

Libraryで説明図の識別と取得準備はできましたが、このクラウドへのバイト転送は `download failed` で失敗し、読めるローカル画像はありません。元PDF・追加JIS素材も未取得です。親側のパスや成功をこの環境のファイルとして扱いません。原票との重ね合わせ・色のRGB確定・残差比較・字体照合は未実施です。

したがって既定背景は `status: missing` です。入力・保存・履歴・CSV・設定・バックアップは使用できますが、本番のプレビュー/PDF/印刷は背景不足を表示して止まります。各帳票の起動診断は、この不足を明示しながら入力・保存機構を確認します。

## 背景を準備する処理

読める元資料がこのクラウドにある場合のみ、例えば次の処理で青印字の候補を作れます。座標は回転補正後の画像に対するピクセル値で、実測した外枠を指定します。

```text
python -B tools/prepare_blue_background.py SOURCE --crop LEFT TOP RIGHT BOTTOM --angle CONFIRMED_ANGLE --width-mm 118.3 --height-mm 176.5 --output PRIVATE_BACKGROUND_JSON
```

PDFは指定ページを既存PyMuPDFで300dpiに描画します。抽出した画素の色は保持し、欠けを埋めたり、引き伸ばして縦横比を合わせたりしません。既存出力を上書きせず、候補の `reviewed` は必ず false です。細字・罫線・手書き除外・外枠・JIS使用範囲を実物で確認した後にのみ、背景設定を帳票設定の `background` へ入れて使用します。確認済みという属性は署名や認証の正当性を証明するものではありません。

背景PNGはbase64とハッシュで利用者の設定に保持し、SQLiteの設定履歴とバックアップへ含めます。原本・背景画素・利用者設定はGitやソース配布へ入れません。将来画像を差し替えても以前の設定履歴を保持します。

## 入力と確認

青固定2項目は入力ウィジェットとCSVに含めません。37黒入力は納入予定値を扱い、初期値は空欄です。予定数量 `005.500`、車両番号 `0012` などの入力文字列を保存時に勝手に整形しません。伝票番号の独立項目・指定チェックシートが未受領のため、納入容積m³合計と件数のみ集計します。

署名と着時刻は `layout_only` を値の有無に関係なくスキップします。設定から別の項目や線を空欄へ入れること、空欄マスクを削除すること、再生成表示を削除・不可視化することを拒否します。

基盤検証は人工の10mmグリッドと架空の試験入力を使います。診断背景は `kind: synthetic_test` / `diagnostic_only: true` として明示し、PDFにも「合成基盤デモ・原票背景未取得」を表示します。これは原票に近づけた完成見本ではありません。クラウドでは既存日本語CID代替フォントを使い、Windows字体・EXE・実印刷は未確認です。

## 納入計画への切替と追加背景

最新指示に基づき、旧「再生成」表示を読みやすい「納入書（計画）」へ置き換えています。実納入の証憑ではありません。既存の記録・訂正履歴の値は変更せず、設定の文書用途と識別表示だけを移行し、以前の表示定義も保持します。

背景設定画面では画像/PDFの選択、外枠の切り出し座標、確認した回転角、未確認候補の保存と再読込ができます。原画像は変更しません。候補は `status: draft` としてSQLite設定履歴とバックアップに保持し、画像を実物で確認するまでは出力を停止します。既知の誤字リストが残る候補は確認済みへ変更しても出力を拒否します。
