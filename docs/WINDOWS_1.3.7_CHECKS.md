# 1.3.7: 入力文字の透過度

既存1.3.6の `input_density` は白方向へのRGB色変更であり、アルファ透過ではなかった。これを互換維持しながら「文字色の濃さ」と明記し、新しい「透過度」を分離する。透過度は0〜100%、0%=不透明・100%=透明。既定値は0%、旧設定に項目がなければ0%扱いとし、旧JSONを開くだけでは書き換えない。

透過対象は可変入力文字と選択印。固定背景画像、固定青文字、固定住所、各伝票枠外の「納入書（計画）」へ適用しない。塗りと線の重なりによる濃い輪郭を避けるため、半透過の入力要素をPDFの独立透明グループで一度だけ合成する。文字色の濃さ・字幅・字間・太さ・入力専用書体・ランダム位置設定と併用できる。

Windowsの本番MSゴシックで全体119テスト完了、失敗0、署名関連2件スキップ。透過度専用5テストは次を検証する。

- 青い下地の上で、50%透過した黒と不透明な50%グレーが異なる画素になること、PDFの塗り・線に実アルファがあること。
- 100%透過では可変文字・選択印だけが消え、通常・伝票印字・太字・ドット印字いずれも空入力時の背景と一致すること。
- 30%の設定保存、再読込、3回プレビューと保存PDFの画素一致、四面付け5件・2ページでも枠外表示を維持すること。
- 透過度がない旧設定と明示0%の描画一致、旧設定の自動上書きがないこと。
- 不正値・範囲外・非有限数値・真偽値を拒否すること。

exeの `--diagnostic` にも、30%透過の3回プレビューと保存PDF画素一致、四面付け、保存先を閉じて再開後の値保持を追加した。診断は隔離先でサンプル計画だけを使う。ユーザー提供の生成背景を基準とし、原本PDFの転送を前提にしない。AC住所照合は別案件として未確認を維持する。
