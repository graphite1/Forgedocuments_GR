# Forgedocuments GR：帳票追加と配布

## 確定した方針（2026-10-14）

Forgedocuments GRを複数帳票のアプリ本体として扱います。現在の運搬明細書は「エーシー帳票」の専用画面です。別の様式を開発した場合は本体へ組み込み、GR Release Hubのアプリ更新で利用者へ追加します。帳票ごとに別アプリを登録しません。

共通部分は起動・帳票選択・PDFプレビュー・更新です。項目、計算、印字、保存先は帳票ごとに管理します。エーシーの項目や計算を新しい帳票に流用しません。原本から読み直し、専用画面を実装します。

## 構成

- `app.py` / `main_app.py`：アプリ本体と帳票選択
- `forms.json` / `form_registry.py`：帳票ID・名称・専用画面の登録
- `ac_screen.py`：エーシー帳票の画面
- `core.py` / `template.json`：現行のエーシー帳票の入力・計算・描画・保存
- `pdf_view.py`：共通PDFプレビュー
- `updates.py` / `update_window.py`：GRHubの署名確認・更新準備・切替
- `tools/build_windows.py`：Windows exeと署名付きZIPの作成

## 新しい帳票の追加

1. 原本の対象枠・全ページを確認し、項目一覧と業務機能を確定します。
2. 専用の画面モジュールと設定・計算・出力処理を作ります。
3. `forms.json` に一意のIDと名称、説明、モジュール名を追加します。
4. モジュールは `App(root, directory)` を公開します。共通契約は `root`、`store.close()`、`may_leave()`、`switch_folder()` です。
5. 帳票ごとに別のデータ保存先を使用し、記録・履歴を混在させません。
6. 新しいモジュールや素材をPyInstallerの対象に含めます。登録だけでは帳票を自動実装しません。
7. 既存帳票と新しい帳票の保存・再読込・出力・プレビュー・更新保持を検証します。
8. アプリ版番号と配布通番を上げ、確定したソースから署名付きZIPを作り、Hubへ公開します。

現時点で選択できるのはエーシー帳票1種類です。任意のPDFを自動認識する機能は実装していません。

## プレビュー

右ボタンを押したままドラッグして移動します。Ctrl＋ホイールでマウス位置を基準に10〜400％で拡大・縮小します。通常のホイールは上下移動です。「全体表示」「100％」「前」「次」も使用できます。

100％は画面上の96dpi基準です。画面の実寸を保証する値ではなく、PDF印刷の原寸指定とは独立しています。

## 保存と旧版からの移行

以前の保存先は `%APPDATA%/AcToyoakeApp/preferences.json` から引き継ぎます。記録を移動せず元の保存先を開きます。本体の帳票ごとの保存先は `%APPDATA%/ForgedocumentsGR/profiles.json` に記録します。

公開版の会社欄は空欄です。会社別 `template.json` はエーシー帳票の「帳票設定」から取り込みます。会社名・住所・連絡先、原本・実記録・署名画像は公開ソースや更新ZIPに含めません。

## 更新

本体の「アプリの更新」から最新情報と変更内容を確認し、ダウンロードします。GRHubのEd25519署名、アプリID、SHA256、展開後のファイル一覧、版とデータ形式を検証します。未保存入力は保存または取消でき、作業中のアプリを強制終了しません。

更新版は `.updates/releases` に準備します。終了後に各帳票のSQLiteと設定を `.updates/backups` へバックアップし、診断と起動確認が成功してから `.updates/current.json` を切り替えます。新しいexeは本体exeや伝票を上書きしません。失敗した場合は以前の起動先を維持します。

今回の更新機構は同じデータ形式（schema 1）に限定します。データ形式を変える場合は互換性・移行・復旧を別途実装・検証します。exeと同梱実行環境は更新ZIPで更新できます。Windows 10/11 x64が対象です。

## 開発と署名

Python 3.14で `requirements-build.txt` を導入し、`python verify.py` と `python verify_platform.py` を実行します。`python tools/build_windows.py --output <新しい出力先>` でexe、署名付きmanifest、Windows ZIPを生成します。

署名秘密鍵はWindows資格情報ストアの `Forgedocuments_GR/release-signing` に保存します。秘密鍵をソース・ファイル・配布物へ出力しません。公開鍵は `update_config.json` に固定します。別PCへの署名鍵移行は別途対応します。

公開先は `https://gr-release-hub.rinntyu2000.chatgpt.site`、アプリIDは `forgedocuments-gr`。公開済みZIPは差し替えず、新しい版・通番を使用します。

## 1.3.5の公開背景例外

利用者の明示承認により、生コンの空欄の計画用背景（社名・住所・JIS図形と計画表示）と専用設定をassets/へ追加した。以前の「原画像を公開しない」という一般方針の限定例外であり、取引値・署名・DB・原本PDF・AC見本は含めない。画像と設定はソースZIPとWindowsビルドで共に同梱し、生コンの新しい保存先で初回から表示する。既存設定は自動置換しない。1.3.5はソース版の確認用候補で、Windows EXE作成・実機検証・正式署名配布は別途必要。
