# Forgedocuments GR

Windowsで使う複数帳票の入力・管理・PDF出力アプリです。このクラウド候補は「エーシー帳票」と「東名太平洋生コン（納入計画）」を搭載しています。現在公開中の1.3.0はエーシー帳票のみです。今後の帳票も専用定義・画面を登録し、アプリ更新で追加します。

生コンは納入計画用として、青印字背景と黒い予定値を合成し、各伝票に「納入書（計画）」を表示します。2026-10-14の提供背景を取得し、許可された誤字修正画像用の独立座標と単票・A4四面付け見本を検証しました。既存設定は自動置換しません。「背景画像を選択」でハッシュ照合できる修正画像を選ぶと、専用寸法・切り出し・入力位置を自動適用できます。修正背景を含む設定JSONの取込にも対応します。本人用の画像同梱ソース版は新規保存先で自動設定し、既存保存先では「同梱の修正背景を選択」で明示適用します。公開ソースには会社画像を含めません。原本・背景・利用者設定はGitに含めず、初期状態では背景の登録が必要です。詳細は [生コン合成方式と確認範囲](docs/TOMEI_FORM.md) を参照してください。

クラウドの新しい正本では、公開済み1.3.0を基に既知の要件を再実装した **1.3.4・通番5の本人確認用候補** を開発しています。会社PCだけにある1.3.2と同一復元ではありません。現在のGRHub配布を置き換えた版ではありません。[今回の実装・検証・保留事項](docs/CLOUD_SUCCESSOR_1.3.3.md) を参照してください。

## 起動

[GR Release Hub](https://gr-release-hub.rinntyu2000.chatgpt.site) からWindows ZIPを取得し、すべて展開して「Forgedocuments GR.exe」を開いてください。Pythonの事前導入・bat操作は不要です。帳票選択画面からエーシー帳票を開き、データ保存先を指定します。入力・保存・PDF出力はオフラインで利用できます。

## 主な機能

- エーシー帳票：入力、保存、訂正履歴、任意の累計計算、CSV取込・書出
- 選択記録・全件のPDF／PNG出力、プレビュー、Windows原寸印刷
- 青文字のドット印字と通常の太字を切替
- 共通プレビュー：右ドラッグで移動、Ctrl＋ホイールでカーソル位置を基準に拡大・縮小
- 全体表示・100％表示・複数ページの前後移動
- 一覧・CSVの実績データから一括出力。選択単票出力と単票手入力も利用可能
- 生成ごとに固有のPDFを使った連続プレビューとキャンセル後の再表示
- 帳票と独立した用紙サイズ・縦横・行数×列数・余白・間隔・原寸／縮小の面付け
- ページごとの印字位置のランダム化（初期OFF、横・縦の幅をmm指定）。数量・日時等の内容は変更しない
- 帳票単位の入力候補・既定値・固定値と、番号・件数・単位別数量の集計確認
- GRHubからの署名付き更新、保存前確認、バックアップ、更新版の起動確認と失敗時の復帰

ACの標準住所「愛知県豊明市栄町神田182」は社名直上の1行・均等字間の固定テンプレート要素で、入力・設定画面からの編集とランダム変位の対象外です。旧標準配置だけを追加的に移行し、独自住所・座標・既存記録・履歴は保持します。原本PDFの転送が失敗しているため、このクラウドでの原本との位置一致・重ね合わせは未確認です。[固定住所の確認範囲](docs/AC_FIXED_FOOTER.md)を参照してください。会社別のtemplate.jsonはエーシー帳票の「帳票設定」から取り込めます。未確認の連絡先は補完しません。原本・個人設定・実績DB・秘密鍵はソースや配布へ追加しません。

「帳票設定」でA4、縦、2行×2列、「枠に合わせて縮小」を選ぶと4伝票を1枚へ配置できます。ACの原寸はこの4枠へ入らないため、原寸指定では設定エラーを表示します。順番は左上→右→次の行。端数枠は空欄です。

入力候補はプルダウンから選べ、文字・数値は候補外も入力できます。既定値は新規入力の開始値で編集可能、固定値は新規入力で編集不可です。設定を変更しても過去の記録は書き換えません。生コン配合の未確認表記や組合せを自動補完する機能はありません。

## 様式の追加と更新

[帳票追加・保存・更新の仕様](docs/PLATFORM.md) を参照してください。項目と計算は帳票ごとに分離します。既存のエーシー項目を別帳票へ固定しません。新しい原本を渡すだけで自動対応する機能は現在ありません。

## 開発

Windowsでは既存のrequirements-build.txtの環境と日本語フォントを使い、`python -B verify_cloud.py` で隔離テストを実行します。Linuxの既存表示環境では `DISPLAY=:99 python -B verify_cloud.py --cid-font` を使用しました。CID代替フォントはテスト専用で、Windowsの字体との一致を保証しません。テスト用の新しい署名鍵は生成せず、公開済み署名fixtureで検証します。

`tools/build_windows.py --unsigned` はWindowsで署名鍵を扱わずEXEと未署名候補ZIPを作成します。正式公開にはWindows起動診断、更新保持試験、既存鍵での署名、GRHubの正規登録・配布確認が必要です。署名付きビルドは既存Windows資格情報ストアの鍵だけを使い、鍵が無い場合や既存公開鍵と一致しない場合は停止します。新しい鍵は作成しません。クラウドではEXEを作成・検証していません。

ソースZIPは変更をコミットした後、`python -B tools/package_source.py --output <保存先>` で作成できます。これはWindows配布ZIPではなく、GRHub更新へ登録できません。

ソースから起動する開発用途ではstart_auto.bat／start.batも残しています。配布版はexeを使用してください。旧版に関するdocs内の起動説明より、このREADMEとPLATFORM.mdを優先します。

構成と新帳票の追加手順は [AGENTS.md](AGENTS.md) に記載しています。用紙配置、入力定義、データ集合の集計、プレビューと更新は共通モジュールに分離し、ACの会社情報・座標・移行は帳票専用モジュールへ限定しています。指定チェックシートと新しい帳票は原本・項目定義の受領後に追加します。

[生コン帳票の仕様と確認範囲](docs/TOMEI_FORM.md)：42項目中37項目を黒で入力し、発行元と原票記載認証文字列は青固定、署名・手書き着時刻の3欄は入力・取込・描画を禁止します。A5原寸配置と欄外組合名を含む面付けに対応し、原票の黒字実績を初期値に残しません。

## 確認範囲

公開済み1.3.0のWindows試験と今回のクラウド後継候補の試験は分けて扱います。今回の結果は [後継候補の確認記録](docs/CLOUD_SUCCESSOR_1.3.3.md) を参照してください。No.の原本照合、Windows EXE、Windows実際のmutex、実機プリンター、更新の実行は未確認です。外周枠117.3×153.0mmはスキャンからの暫定換算値で、用紙上の倍率と別に設定できます。
